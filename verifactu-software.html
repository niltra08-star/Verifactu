Software Verifactu Gratis

Que hace que un software de facturacion sea compatible con VeriFactu. Requisitos tecnicos, proceso de certificacion y como FacturaIA los cumple todos.

Que significa que un software sea "VeriFactu compliant"

Que un software de facturacion sea compatible con VeriFactu no es una etiqueta comercial que cualquier empresa pueda ponerse. Significa que el software cumple con un conjunto muy concreto de requisitos tecnicos y funcionales establecidos por la Agencia Tributaria en el Reglamento que desarrolla la Ley 11/2021 de lucha contra el fraude fiscal.

Estos requisitos no son orientativos ni recomendaciones: son de obligado cumplimiento. El Reglamento de VeriFactu especifica al detalle que mecanismos debe implementar el software, como debe estructurar los datos, que algoritmos criptograficos debe usar y que informacion debe incluir cada factura para ser considerada valida.

Un software VeriFactu compliant debe garantizar, como minimo, la integridad, conservacion, accesibilidad, legibilidad, trazabilidad e inalterabilidad de los registros de facturacion. Esto no se consigue con un simple programa que genere PDFs con un QR bonito. Requiere una arquitectura de software disenada especificamente para cumplir con estos requisitos.

Requisitos tecnicos que debe cumplir un software VeriFactu

El Reglamento de VeriFactu detalla los siguientes requisitos tecnicos que todo software de facturacion debe implementar:

1. Encadenamiento de hashes (hash chain) SHA-256

Cada factura debe incluir la huella digital (hash) de la factura inmediatamente anterior, calculada mediante el algoritmo SHA-256. Esto crea una cadena criptografica donde cada eslabon depende del anterior. Si se modifica una factura antigua, su hash cambia y la cadena se rompe, haciendo detectable cualquier manipulacion. El software debe generar y mantener esta cadena automaticamente, sin intervencion del usuario. No se puede desactivar.

2. Codigo QR verificable

Cada factura debe incluir un codigo QR que contenga, como minimo: el NIF del emisor, el numero de factura, la fecha de emision, el importe total y el hash de verificacion. Opcionalmente puede incluir mas datos. La AEAT debe poder verificar la autenticidad de la factura escaneando este QR, incluso sin acceso al sistema del emisor. El formato del QR sigue la especificacion publicada por la AEAT.

3. Formato FacturaE 3.2 o superior

Las facturas deben generarse en el formato electronico estructurado FacturaE, version 3.2 o superior. Este formato XML es el estandar publico espanol de factura electronica. El software debe incluir en el FacturaE los campos especificos de VeriFactu: hash de la factura anterior, hash de la factura actual, datos para el QR y marca de tiempo de generacion.

4. Firma digital (opcional pero recomendable)

Aunque no es estrictamente obligatorio en la fase inicial para facturas B2B, la firma electronica avanzada (XAdES) anade una capa adicional de seguridad y autenticidad. Un software VeriFactu completo debe ser capaz de firmar electronicamente las facturas. FacturaIA soporta la firma electronica de facturas para quienes deseen este nivel adicional de seguridad.

5. Registro de eventos inalterable

El software debe mantener un registro cronologico (log) de todas las operaciones relacionadas con la facturacion: creacion de facturas, anulaciones, rectificaciones, modificaciones de datos maestros. Este registro debe ser inalterable y auditable. En caso de inspeccion, la AEAT puede solicitar este registro para verificar la trazabilidad de todas las operaciones. El registro no puede ser editado ni eliminado por el usuario.

6. Numeracion correlativa y sin saltos

Cada factura debe tener un numero unico y correlativo dentro de su serie. El software debe garantizar que no se pueden producir saltos en la numeracion, duplicados ni huecos. Las facturas anuladas deben mantener su registro con la marca de anulacion, pero el numero no se reutiliza. La AEAT cruza la numeracion para detectar facturas no declaradas.

Como FacturaIA cumple con todos los requisitos de VeriFactu

FacturaIA fue disenado desde el primer dia para cumplir integramente con la normativa VeriFactu. No es una adaptacion apresurada de un software antiguo: toda la arquitectura se construyo pensando en los requisitos del Reglamento. Estos son los detalles de implementacion:

  • Hash chain SHA-256: El backend de FacturaIA, desarrollado en Java con Spring Boot, calcula el hash SHA-256 de cada factura utilizando la libreria criptografica estandar de Java (MessageDigest). El hash de la factura N se almacena y se incrusta en la factura N+1. La cadena se mantiene incluso si anulas una factura: la anulacion tambien genera un registro en la cadena.
  • QR verificable: El codigo QR se genera en el frontend utilizando la libreria qrcode.js, con los datos estructurados segun la especificacion de la AEAT. El QR incluye el NIF, numero de factura, fecha, importe y hash.
  • FacturaE 3.2: El XML FacturaE se construye cumpliendo estrictamente el esquema oficial publicado por el Ministerio de Hacienda. Los campos VeriFactu (hash chain, QR data) se mapean a las extensiones correspondientes del esquema 3.2.
  • Registro de eventos: Todas las operaciones de facturacion quedan registradas en la base de datos con marca de tiempo y hash. El registro no puede ser editado ni eliminado por el usuario. En la version open source, el registro se almacena en PostgreSQL con triggers que impiden modificaciones.
  • Numeracion garantizada: El sistema utiliza secuencias atomicas de base de datos para garantizar la numeracion correlativa sin posibilidad de duplicados ni saltos, incluso en condiciones de alta concurrencia.

El proceso de certificacion de software VeriFactu

La AEAT ha establecido un proceso de certificacion para el software de facturacion. Aunque los detalles finales pueden variar cuando se publique el reglamento definitivo, el procedimiento general es el siguiente:

  1. Desarrollo conforme a especificaciones: El software se desarrolla siguiendo estrictamente las especificaciones tecnicas publicadas por la AEAT
  2. Pruebas de conformidad: La AEAT publicara un conjunto de pruebas (test suite) que el software debe superar para demostrar que cumple con los requisitos
  3. Auto-declaracion responsable: El fabricante del software emite una declaracion responsable afirmando que su producto cumple con la normativa VeriFactu
  4. Registro en el censo de software: La AEAT mantendra un registro publico de software certificado. Los programas que no figuren en este registro no podran ser utilizados para facturar
  5. Auditorias periodicas: La AEAT puede realizar auditorias tecnicas para verificar que el software sigue cumpliendo los requisitos

FacturaIA, al ser open source, ofrece una ventaja adicional en el proceso de certificacion: el codigo fuente es publico y auditable. Cualquier persona, incluida la propia AEAT, puede examinar el codigo para verificar que los mecanismos de hash chain, generacion de QR y construccion del FacturaE se implementan correctamente. No hay cajas negras.

Por que elegir un software VeriFactu open source

Que el software de facturacion sea open source no es solo una cuestion de precio (que tambien, al ser gratuito). Hay razones de fondo por las que el codigo abierto es la mejor opcion para cumplir con VeriFactu:

  • Transparencia total: Puedes ver exactamente como se calculan los hashes, como se genera el QR y como se construye el XML. No dependes de la palabra de un comercial.
  • Auditabilidad: Tu asesoria fiscal o un perito informatico puede auditar el codigo para verificar que cumple con la normativa. Con software propietario, esto es imposible.
  • Independencia del fabricante: Si la empresa que fabrica tu software de facturacion cierra o decide triplicar sus precios, con software propietario estas atrapado. Con open source, el codigo es tuyo y de la comunidad. Siempre podras migrar o contratar a alguien para que lo mantenga.
  • Seguridad reforzada: Al ser el codigo publico, mas ojos lo examinan y los fallos de seguridad se detectan y corrigen mas rapidamente que en el software cerrado.
  • Sin coste de licencia: No pagas por usar el software, ni por actualizaciones, ni por nuevas versiones. El unico coste es el de la infraestructura si decides alojarlo tu mismo, o cero si usas la version en la nube de FacturaIA.

Preguntas frecuentes sobre software VeriFactu

1. ¿Mi software de facturacion actual cumplira con VeriFactu?

Depende del software. Muchos programas de facturacion tradicionales (especialmente los de escritorio y los basados en Excel) no cumpliran porque su arquitectura no esta disenada para implementar hash chains, QR VeriFactu ni FacturaE. Los grandes proveedores de software (Holded, Quipu, Anfix, Sage) estan adaptando sus productos, pero en muchos casos las funcionalidades VeriFactu solo estaran disponibles en sus planes de pago superiores. Con FacturaIA no tienes ese problema: VeriFactu esta integrado desde la primera version y siempre sera gratuito.

2. ¿Puedo usar FacturaIA aunque ya tenga otro software?

Si. Muchos autonomos utilizan FacturaIA como complemento o sustituto de su software actual. Como es completamente gratuito, no hay riesgo en probarlo. Puedes empezar creando algunas facturas en paralelo con tu sistema actual para comparar y decidir cual te convence mas. Si decides migrar por completo, puedes exportar tus datos de tu antiguo software e importarlos en FacturaIA.

3. ¿Como se que FacturaIA seguira cumpliendo la normativa en el futuro?

FacturaIA es un proyecto open source mantenido activamente por una comunidad de desarrolladores. Las actualizaciones normativas se implementan de forma colaborativa, a menudo mas rapido que en el software comercial. Ademas, al ser open source, si en el futuro la comunidad dejara de mantenerlo (algo improbable, pero posible), cualquier desarrollador podria tomar el codigo y continuar con las actualizaciones. No dependes de una unica empresa.

4. ¿El software VeriFactu tiene que enviar las facturas a la AEAT automaticamente?

En la fase inicial de implantacion de VeriFactu, el envio automatico de facturas a la AEAT no es obligatorio para todos los casos. Sin embargo, el software si debe ser capaz de generar las facturas con todos los elementos de verificacion y los registros deben estar disponibles para su remision si la AEAT los solicita. La obligacion de envio automatico se ira implantando de forma progresiva en fases posteriores. FacturaIA esta preparado tanto para la situacion actual como para las futuras fases de implantacion.
